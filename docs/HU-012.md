# HU-012 — Implementación del microservicio de datos no estructurados

## 1\. Descripción

Como parte de la arquitectura de Kora, se implementó el microservicio `svc-unstructured-data`, responsable de gestionar la información no estructurada del sistema.

El microservicio fue desarrollado como una aplicación Django independiente y cuenta con una API REST mediante Django REST Framework. Su persistencia se realiza exclusivamente mediante MongoDB, de acuerdo con la arquitectura establecida para Kora.

La implementación permite disponer de un servicio independiente que puede ser consumido por los demás componentes del sistema sin depender directamente de sus bases de datos.

## 2\. Tecnologías utilizadas

Para la implementación se utilizaron las siguientes tecnologías:

|Tecnología|Propósito|
|-|-|
|Python|Lenguaje de programación|
|Django|Framework principal del microservicio|
|Django REST Framework|Desarrollo de la API REST|
|MongoDB|Persistencia de datos no estructurados|
|PyMongo|Conexión y comunicación con MongoDB|
|Docker|Ejecución local de MongoDB durante el desarrollo|

## 3\. Estructura del microservicio

El microservicio cuenta con una estructura independiente de los demás servicios de Kora. La aplicación Django contiene los componentes necesarios para exponer la API, administrar la configuración y establecer la conexión con MongoDB.

La persistencia no utiliza el ORM de Django. En su lugar, los documentos son gestionados directamente mediante PyMongo, debido a la naturaleza flexible de los datos almacenados.

## 4\. Configuración de MongoDB

La conexión con MongoDB se configura mediante variables de entorno para evitar que los datos de conexión queden definidos directamente en el código fuente.

La variable utilizada es:

```text
MONGODB\_URL
```

La aplicación crea un cliente de MongoDB a partir de esta URI y obtiene la base de datos especificada en ella.

Durante el desarrollo local se utilizó una instancia de MongoDB ejecutada mediante Docker.

La conexión fue validada mediante una operación `ping` contra el servidor de MongoDB, confirmando que el microservicio puede establecer comunicación con la base de datos.

## 5\. Estructura de los documentos

Debido a que el microservicio administra información no estructurada, los documentos almacenados en MongoDB utilizan una estructura flexible.

Se estableció una estructura base compuesta por los siguientes campos:

|Campo|Descripción|
|-|-|
|`\_id`|Identificador generado por MongoDB|
|`type`|Tipo de documento|
|`user\_id`|Identificador del usuario asociado|
|`source`|Servicio que originó la información|
|`created\_at`|Fecha y hora de creación|
|`data`|Contenido específico del documento|

El campo `data` permite almacenar información variable dependiendo del tipo de documento.

Los tipos contemplados inicialmente son:

* `activity\_log`
* `history`
* `ai\_result`
* `flexible\_data`

Esta estructura permite mantener una base común para los documentos sin imponer un esquema relacional rígido.

## 6\. API del microservicio

Se implementó un endpoint inicial para verificar el funcionamiento del servicio:

```text
GET /api/health/
```

La respuesta esperada es:

```json
{
  "status": "ok"
}
```

Este endpoint permite comprobar que la aplicación Django está ejecutándose correctamente y que la API se encuentra disponible.

## 7\. Configuración de Django REST Framework

El microservicio no administra la identidad ni la autenticación de los usuarios. Esta responsabilidad corresponde a `svc-identity`, de acuerdo con la arquitectura establecida para Kora.

Por este motivo, se modificó la configuración predeterminada de Django REST Framework para evitar la dependencia del sistema de autenticación de Django en este microservicio.

La configuración establecida es:

```python
REST\_FRAMEWORK = {
    'DEFAULT\_AUTHENTICATION\_CLASSES': \[],
    'DEFAULT\_PERMISSION\_CLASSES': \[],
    'UNAUTHENTICATED\_USER': None,
    'UNAUTHENTICATED\_TOKEN': None,
}
```

Con esta configuración, el servicio puede utilizar Django REST Framework sin requerir `django.contrib.auth` ni `django.contrib.contenttypes` para sus endpoints actuales.

## 8\. Separación de persistencia

Como parte de la arquitectura de Kora, `svc-unstructured-data` no utiliza una base de datos relacional propia.

La configuración de Django utiliza el backend `dummy`:

```python
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.dummy',
    }
}
```

Esto evita que Django utilice SQLite u otro motor relacional mediante su ORM.

La persistencia real del microservicio se encuentra en MongoDB y se administra mediante PyMongo.

## 9\. Resultado de la implementación

Con la implementación de HU-012 se estableció la base funcional del microservicio `svc-unstructured-data`.

El servicio cuenta con:

* Proyecto Django independiente.
* Django REST Framework configurado.
* Conexión funcional con MongoDB.
* Estructura inicial para documentos flexibles.
* Tipos de documentos definidos.
* API propia.
* Endpoint de health check.
* Ausencia de dependencia de una base de datos relacional.
* Configuración preparada para la futura comunicación con otros servicios de Kora.

Esta implementación constituye la base sobre la cual se desarrollarán posteriormente las operaciones CRUD de los documentos almacenados en MongoDB.
